ADPS Agent Design Pattern White Paper

G4 · Observability Harness

Build agent evidence from events, causality, versions, state deltas, and external receipts.

G4 uses typed events, causal identity, version references, state deltas, and external receipts to turn a run into evidence that can be queried, evaluated, and attributed.

v0.4 classification

Cross-cutting core · Observation and evidence plane. G4 no longer occupies Governance × Orchestrate. It spans every function, topology, and lifecycle stage, while the core total remains 28.

From logs to evidence

LayerFactsUse
Input and contextSource, version, admission and rejectionReconstruct what the agent could see
Decision and planGoal, step, route, candidates, decision summaryDiagnose drift, routing, and planning
Action and controlTool, argument provenance, identity, policy, approval, quotaAudit and invocation attribution
State and outcomeState delta, receipt, business acceptance, human editDetect false success and actual impact
FoundationModel, prompt, skill, knowledge, tool, policy versionsCompare versions and locate regression

Full hidden model reasoning is an unstable and sensitive telemetry target. Structured decision summaries, candidates, references, calls, and state changes usually form better operational evidence.

Causality and identity

principal → agent → workload → session → run → intent
          → approval → model/tool/sub-agent span → resource → outcome

Trace Context propagates across processes, while business objects retain stable IDs. A retry creates a span, not a new intent or duplicate effect.

Three observation levels

Task and business outcome covers goal completion; agent process covers context, planning, tools, and recovery; foundation covers model, RPC, storage, and policy health. Join all three by run, version, and outcome.

Running example

A payroll evidence chain connects the source ledger, goal contract, intent, policy verdict, approval view, invalidation during the wait, replacement approval, tool request, payment receipt, ledger delta, and reconciliation. This separates planning error, stale approval, duplicate submission, and API success without business completion.

Failure and verification

Failures include unconnected text logs, treating HTTP 200 as completion, broken links across agents and callbacks, easy-task sampling, unlimited sensitive retention, and mixing judge scores with observed facts.

Verify trace continuity, identity and version completeness, external confirmation for side effects, orphaned writes, evidence latency, sampling bias, and sensitive-evidence access. Test process boundaries, retry, resume, model fallback, schema migration, and collector outage.

Public implementation

DeerFlow Guardrail exposes public code paths between identity, authorization verdicts, RunJournal, and tool execution. Domain state deltas and external outcomes remain integration responsibilities.
