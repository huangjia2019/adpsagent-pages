本次研讨以 R1–R5 的公开规范为基础，检查推理在生产系统里的输入、输出、资源预算、验证和停止条件。

讨论范围

  1. 哪些请求值得进入深度推理，哪些可以由规则或轻量路径处理？
  2. 复杂度、风险、证据缺口和时延目标怎样共同影响路由？
  3. 并行分支怎样保持独立，又怎样在超时和冲突后收口？
  4. 循环推理在什么条件下停止、转交人工或放弃当前假设？
  5. 怎样保存可审计的依据，同时不把模型私有推理 token 当成事实？

当前模式目录

模式工程职责
R1 思维链管理推理摘要、证据绑定、决策记录与模型元数据
R2 复杂度路由选择模型、推理深度、成本档位与回退路径
R3 并行探索隔离候选路径，并按业务错误代价聚合
R4 迭代假设验证用新证据更新假设，直到收敛或达到退出条件
R5 双模架构分离实时交互与后台深度推理

一个组合示例

线上服务出现间歇性超时，日志里同时出现网络抖动、配置变更和数据库慢查询。系统先用 R2 判断这不是可以直接套规则的普通告警，并设置时间与调用预算。R3 启动三个隔离分支，分别检查网络、配置和数据库；各分支只能读取同一份带时间戳的证据快照，不能看到其他分支的中间结论。

聚合节点发现配置分支有直接证据，数据库分支仍有疑点，于是进入 R4：先在灰度实例复现，再验证回滚配置能否消除超时。若证据仍无法区分两个假设，系统携带假设树、已做检查和未决问题转交值班人员。R5 的交互者在这段时间只报告进度和继续收集事实，不自行宣布根因。最终决策记录交给行动模块，回滚权限仍由治理模块检查。

阅读路径

先读推理模块总纲，确认推理产物与相邻模块的接口；再根据任务结构选择单个模式。需要改变外部系统时，继续检查行动模块与治理模块。需要证明判断质量时，使用X2 评测与验证。
