团队介绍

创始成员、顾问，与专家组。

ADPS 汇集了 Agent 架构、软件工程、开源基础设施和企业系统落地领域的研究者与实践者。 团队共同维护模式目录，发布参考资料，并用可运行系统和一线案例持续检验这套模式语言。

蓝皮书贡献者

模式规范来自公开研究与书稿，但模式能不能站住，要看它在真实系统里是否被反复用到、 在什么条件下失效。这一层证据只能由一线实践者提供。下面记录向共同体交付过 案例报告的贡献者与所在机构，以便读者判断证据的来源与边界。

梁博（Bo Liang）

案例报告 01 · 企业 SaaS · 执行型 Agent

上海东方屹腾科技有限公司副总裁，同时是 ADPS 创始成员（详见上方创始成员一节）。

贡献 案例报告 01 · 东方屹腾执行型 Agent 从零到稳定交付。 报告记录了一套企业 SaaS 业务流程自动化 Agent 的完整演进：为什么 MCP 那套让模型生成参数的做法在执行型场景里走不通， 控制平面与叙事平面怎么分开，机械状态平面怎么解决长随机 ID 的传递问题，以及会话统一状态平面的三权分立结构。

熊钰柯（Yuke Xiong）

案例报告 02 · 地理信息 · 领域 Agent

玄宿科技技术架构师、创业合伙人，长期在「GIS 加」领域主导产品与项目落地， 目前专注于把 Agent 能力嵌入并赋能企业级业务系统。 玄宿科技是一家专业从事 GIS 软件产品及系统研发与服务的高新技术企业， 拥有自主知识产权的国产化二次开发框架，具备基于「GIS 加二三维可视化」的基础底座支撑能力。

贡献 案例报告 02 · 玄宿科技 GIS 数据发布 Agent。 报告记录了一个把决策整体前置到设计期的领域 Agent：运行期整条链路没有任何模型调用， 路由是查表，编排是静态六阶段链，而系统仍具备感知、决策、行动、验证、回退、生长的完整闭环。 报告提出的「推理资产化」「磁盘事实平面」「失败日记器官化」，为强规则、精确数据类行业提供了一条可参照的路径。

在 ADPS 的工作：强规则、精确数据处理类行业的落地证据。验证「Agent 负责理解意图与串联流程，领域专业工具继续负责精确计算与执行」这条分工在生产系统里的边界。

袁良锭（Yuan Liangding）

案例报告 03 · MBSE 与工业软件 · 建模 Agent

Ark · 雅格创始人，成都，十六年工业软件与平台研发经验， 早期做过流程管理、搜索、协作与知识系统，现在专注于把 AI 辅助的 SysML / MBSE 方案产品化。 Ark · 雅格的定位是工业 MBSE × AI，产品线包含旗舰产品 AI4MBSE、面向建模任务的工程知识库， 以及 MagicGrid、OOSEM、Harmony-SE 三套方法论的配置支持。

贡献 案例报告 03 · 自然语言到 SysML：一张图交付的建模 Agent。 报告记录了一个把交付物定义为工程状态而非文字的建模 Agent：主链拆成元素、关系、视图三段契约， 结构坐标由程序与工程索引保管，模型只在白名单内起草，写回前由确定性门禁裁决。 报告详述了五类「成功的假结构」幻觉及其卡口，也交代了砍掉模型自评闭环的完整理由。

在 ADPS 的工作：结果必须写进正式模型库、错一位就伤存量工程这类场景的落地证据。 报告提供了第三个独立行业的样本，支持「机械坐标不交给模型生成」这条跨案例观察， 同时给出了「要不要上反思环取决于错误能否离线判定」这条判据。

案例报告署名到具体贡献者与所在机构。机构信息由贡献者提供，业务规模与效果数据未经独立审计。 收录不等于产品认证，也不构成普遍适用性背书。欢迎经加入我们提交新的案例报告或模式修订。
