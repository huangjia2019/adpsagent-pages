署名政策
案例署名到人与机构

ADPS 的模式规范来自公开研究与书稿，但模式能不能站住，要看它在真实系统里是否被反复用到、在什么条件下失效。这一层证据只能由一线实践者提供。

本页记录向共同体交付过公开材料的贡献者。案例报告署名到人，同时标注其所在机构与该机构提供的场景，以便读者判断证据的来源与边界。

蓝皮书贡献者

蓝皮书案例报告由一线实践者主导复盘，交代系统约束、实现结构、已知失败与迁移边界。收录不等于产品认证，也不构成普遍适用性背书。

梁博（Bo Liang）

上海东方屹腾科技有限公司 副总裁 · 创办期股东与合伙人

负责技术与产品。东方屹腾核心团队来自银行互联网渠道领域，聚焦银行泛金融生态场景的 SaaS 服务。其薪享通 SaaS 服务矩阵已与 20 余家银行建立联合运营体系，服务 5 万余家企业客户，目前正把整个 SaaS 产品矩阵转型为 Agent 体系。

他同时是 ADPS 的创始成员之一，在共同体里承担企业部署证据与金融 SaaS 向 Agent 转型的一线实践这条线。

贡献的案例报告：案例报告 01 · 东方屹腾执行型 Agent 从零到稳定交付

这份报告记录了一套企业 SaaS 业务流程自动化 Agent 的完整演进：为什么 MCP 那套让模型生成参数的做法在执行型场景里走不通，控制平面与叙事平面怎么分开，机械状态平面怎么解决长随机 ID 的传递问题，以及会话统一状态平面的三权分立结构。报告里那句「团队要的是确定，确定就不能只靠概率」，后来成了共同体讨论执行型场景时反复引用的判据。

在 ADPS 的工作：企业部署证据，金融 SaaS 向 Agent 系统转型的一线实践。把模式语言放进银行泛金融、HR SaaS、薪酬、考勤、个税、薪资代发等复杂业务流程里验证，并持续把真实企业问题、架构反馈与产品边界带回框架。

熊钰柯（Yuke Xiong）

成都玄宿科技有限公司 技术架构师 · 创业合伙人

成都玄宿科技是一家专业从事 GIS 软件产品及系统研发与服务的高新技术企业，拥有自主知识产权的国产化二次开发框架，具备基于「GIS 加二三维可视化」的基础底座支撑能力。

他长期从事软件研发，在「GIS 加」领域深度参与并主导产品与项目的落地实施，维护二次开发框架，目前专注于把 Agent 能力嵌入并赋能企业级业务系统。

贡献的案例报告：案例报告 02 · 成都玄宿 GIS 数据发布 Agent

这份报告记录了一个把决策整体前置到设计期的领域 Agent：运行期整条链路没有任何模型调用，路由是查表，编排是静态六阶段链，而系统仍然具备感知、决策、行动、验证、回退、生长的完整闭环。报告里提出的「推理资产化」「磁盘事实平面」「失败日记器官化」三个说法，给强规则、精确数据类行业提供了一条可参照的路径。

他自己对双轴框架的使用心得是：专业领域 Agent 相比通用 Agent，在一些地方必须取舍，而这套框架最大的价值是让人看清楚哪些是必须取舍的。这份案例报告里那张 42 格落位图，把取舍逐格标了出来，包括主动留空的格子和判定存在分歧的格子。

在 ADPS 的工作：强规则、精确数据处理类行业的落地证据。验证「Agent 负责理解意图与串联流程，领域专业工具继续负责精确计算与执行」这条分工在生产系统里的边界。

怎样成为贡献者

共同体接收两类贡献。

案例报告是完整系统的架构记录，以系统为单位，需要交代运行约束、失败历史、架构决策、证据边界与迁移条件。一份报告可以跨越多个模式，正文中的模式切片链回白皮书定义。案例报告经共同体公开评审后收录。

模式修订是对已发布模式规范的补充或反驳，包括新的失效方式、新的适用条件，或者对某个坐标判定的异议。共同体欢迎带证据的反驳，尤其欢迎「这个模式在我们的场景里不成立」这类材料。

两类贡献都可以经加入我们页面提出。

署名政策：案例报告署名到具体贡献者与所在机构。机构信息由贡献者提供，业务规模与效果数据未经独立审计。
