系统边界与状态7

识别控制权、事实状态和运行边界分别由谁持有。

控制平面与叙事平面

控制信号驱动程序分支，叙事上下文为模型推理提供语义输入。

执行型与内容生成型 Agent

按交付对象、状态依赖和错误成本选择运行时机制。

会话统一状态三平面

SessionNarrative、SessionState 和 Workspace 分别管理语义、参数与调度。

机械状态平面

业务参数由程序按来源坐标传递，不经模型重新生成。

Orchestrator 与门面

Orchestrator 管理控制流，MessageHandler 负责输入适配和流式呈现。

磁盘事实平面

以版本化外置合同承载阶段事实、运行状态和验收证据。

概率内核与确定性外壳

模型处理开放判断，确定性机制守住生产边界。

上下文与记忆6

处理信息如何进入上下文、跨步骤保留并在需要时重新取回。

锚、账、集

Anchor 保存目标，Ledger 追加事实，Collection 提供当前读取视图。

草稿纸看板

用结构化字段保存当前目标、步骤、观察、阻塞、证据和下一动作。

记忆信封

ReasonContext 按步骤组装目标、进展、意图结论和相关经验。

L1/L2/L3 分层记忆

当前输入、任务事实和跨任务经验分层存储，完整事实按引用加载。

知识编译

把知识源转换成可直接消费、可追溯、可增量更新的运行资产。

上下文合同

规定一类任务允许进入推理窗口的信息、来源、时效与预算。

推理与行动机制3

比较模型如何在思考、观察、代码和工具调用之间推进任务。

ReAct 推理—行动循环

在推理与行动之间交替推进，让下一步使用刚获得的外部观察。

程序化工具调用

让模型生成一段受限程序，批量调用已注册工具并在进入上下文前处理结果。

CodeAct：代码即行动

把可执行代码作为 Agent 的行动语言，用同一空间完成计算、库调用与工具组合。

规划、执行与写回9

把意图变成可调度步骤，并控制中间表示与业务结果的写回。

意图即编译

入口分类器输出有限枚举，异常结果进入 unknown 兜底。

任务 DAG 与状态机

依赖边限定执行顺序，节点状态支持调度、验收和恢复。

推理资产化

设计期形成可审阅、可认证的能力资产，运行期消费指定版本。

类型化中间表示链

自然语言逐段收敛为可验证、带类型和稳定引用的候选结构。

单图事务

一种图、一个已解析范围、一次写入和一份回执构成提交边界。

结构写回门禁

候选结构通过范围、类型、引用、完整性和真实增量检查后才能写入。

可续跑澄清作业

缺少信息时冻结同一作业，保存已确认字段、候选项和恢复游标。

词表等价层

以版本化映射对齐规划词表、领域类型和宿主元模型。

Plan 编译

把推理产出的计划转换为带依赖、类型、权限和验收的可执行结构。

协作与运行时控制7

处理多参与者之间的交接、并发、职责和运行时组合。

拓扑降阶

把高层协作语义编译为串行、并行和路由等运行原语。

拓扑治理矩阵

用身份、权限、防护与溯源检查串行、并行和路由结构。

交接合同

在一次交接中共同转移目标、产物、决定、权限、责任和验收。

三类协作关系

同时审查 Agent-Agent、Human-Agent 与 Agent 环境中的 Human-Human。

Hook 组合

在生命周期事件上组合编排、治理、观测和恢复动作。

统一收敛节点

让多条推理分支按同一组证据和裁决规则形成一个可执行结论。

写入冲突域

识别并行任务可能共同改变的文件、标识、配置、领域对象和外部环境。

评测、反思与治理12

定义谁来判断结果、如何回收反馈，以及什么条件下允许系统继续行动。

活动事件与执行时间线

Activity 与 Frame 关联模型、工具、状态变化、耗时和成本。

HITL 阻塞与恢复

敏感节点暂停并保存状态，审批后重新校验并继续执行。

外部验收探针

从用户一侧发出真实请求，以状态、内容和可见结果裁决成功。

失败到规则闭环

事故卡回链规则、默认值、约束或测试，并由后续同类任务验证。

能力认证生命周期

能力按 draft、candidate、active 逐步取得运行权，版本漂移后自动失效。

双反馈时钟

把任务内即时反馈与跨任务延迟结果分开处理。

持久化意图

让审批等待与恢复执行指向同一个不可变动作。

Agent 的三种权力

从信息、裁决和行动三个入口检查 Agent 获得了什么权力。

裁判迁移

跟踪验收标准怎样从需求阶段移交到测试、评审、部署和业务结果。

双尺度治理

同时约束当前动作与长程目标，避免每一步合规却逐渐偏离任务。

场景–Benchmark 契约

用生产场景与对应评测集共同规定能力边界、准入线和换版条件。

业务评测集

用业务流程、代表场景、权重和指标判断技术改动是否改善了业务结果。
